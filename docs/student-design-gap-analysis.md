# Student design and machining integration: gap analysis

Audit date: 24 October 2026. Initial baseline: `abe5869`; updated after the parallel CNC release `4330ada` was incorporated. Scope: ACCESS Numeracy Hub, Shape Canvas, CNC learning tools, and the supplied desktop design references.

## Decision

Build one student method, **Brief → Draw → Check → Machine → Reflect**, around a versioned project with physical dimensions. Keep the existing Shape Canvas as the capable drawing and numeracy workspace. Add a guided entry point and an explicit geometry handoff to machining. The first release should complete this method for a small, well-defined set of parts; subsequent releases should expand the same contract.

“Integrate everything” is treated as a complete capability map and an ordered implementation programme. It does not mean that native desktop applications, their executable files, or every CAD/CAM feature can be embedded in an offline browser page.

## The student method

The target method keeps the same project name, units, part, and next action visible across stages, with revision context added when operation history is introduced. Students can revisit an earlier stage; a material edit refreshes checks and must invalidate dependent machining preparation. A stage indicator is navigation, not a claim that a student has completed or mastered it.

| Stage | Student question | Minimum interaction | Evidence carried forward |
|---|---|---|---|
| Brief | What am I making, and what must it fit? | Select a starter, name the part, state its purpose, choose display units, and enter stock dimensions. Show a labelled example. | Purpose, part family, canonical dimensions, stock, chosen coordinate origin, and optional requirements. |
| Draw | How will I describe its size and shape? | Enter dimensions with immediate preview; open the same supported part in Shape Canvas; use the existing formulas and dimension tools. | Parametric geometry and its source revision. Drawing annotations remain presentation information. |
| Check | Does my design meet the brief? | Show calculated values, dimensional validity, stock fit, unit interpretation, and an explicit list of remaining issues. Link each issue to the relevant field. | Check results associated with the exact project/geometry revision, plus the student's estimate or explanation. |
| Machine | How would the part be set up and made? | Show process, stock, origin, intended operation, and the connection to the CNC learning simulator. Separate simulation from physical-machine output. | A validated teaching handoff with units and geometry; later, operations/tool choices and simulation evidence. |
| Reflect | What did I learn or change? | Record a calculation, explain one design change, and compare the result with the brief. Save an editable project and a useful presentation/export. | Reflection and revision context; later, teacher feedback and criterion-level assessment. |

Beginner mode should start from a plate, washer, or shaft and expose one decision at a time. Advanced mode should expose the same model's dimensions, setup, coordinates, and interchange choices without a different file format. Learners must not lose existing work when changing mode. “Advanced” means more control; it does not remove dimensional validation.

The first user test is deliberately practical: a student creates a dimensioned part, edits it in the canvas, checks its fit, reaches the machining activity, explains one result, and reopens their saved work without re-entering any dimensions.

## Canonical data and geometry contract

Use a design project envelope for the new method; keep legacy canvas drawings readable. Canonical physical lengths are mm. Display units and formatting are presentation choices. Retain full numeric precision in the model and round at display/export boundaries according to the specified purpose. Degrees/radians and area/volume powers must be explicit wherever values cross module boundaries.

The longer-term contract should identify schema/version, project/part IDs, revision, brief, part type and dimensions, display units, stock dimensions, origin/setup, check results, reflection, and provenance. The current version implements project identity, brief, dimensions, display units, stock, fixed-origin placement, and reflection; it recomputes checks rather than storing them. Durable revision/provenance and operations are further extensions, not present schema fields. Do not put interface HTML, SVG presentation annotations, or executable expressions in the model.

Canvas adapters must use `SC.M`'s semantic dimensions and document units. They must not derive a radius or part width from `getBoundingClientRect`, the page's zoom, a PDF paper scale, or `SC.A.exportSvg`'s presentation bounds. Baseline `M.addShape` uses `M.fitPpu` to fit each object on screen; two equal-looking objects can therefore represent different physical sizes.

For the initial subset, a single supported part can transfer by shape ID plus dimensions, with an explicit local origin. This is more precise than interpreting arbitrary page positions. A later multi-object adapter needs a declared common scale and a complete transform: local object → assembly → stock/work coordinates. Specify handedness and Y direction, and test rotation/mirroring separately. Closed loops, holes, and construction geometry need different semantics.

Stock must distinguish rectangular material from round stock, and 2D outline from 3D dimensions. A cylinder side view does not by itself define a turning setup. A washer outline does not by itself define drilling versus pocketing versus profiling. Keep **geometry**, **process intent**, **toolpath**, and **machine program** as distinct data stages. The existing CNC simulator uses inches internally in parts of its project model: `CNCManual.project` converts its mm/in setup to that representation. The design adapter should enter through `CNCManual`/builder APIs and respect their conversion, precision, and stock limits; it must not send canonical-mm stock straight into an internal-inch simulator object.

Checks should be pure functions of validated project data. A passing check must state its scope: for example “fits inside stock” is narrower than “ready to machine.” A change to dimensions, stock, units interpretation, origin, or operation inputs invalidates dependent results. Use project identity and revision/content fingerprints to prevent a late response from one canvas tab overwriting a newer project in another tab.

## Persistence, undo, and import behaviour

Preserve the baseline canvas's document and assets when introducing design metadata. A shared-project envelope or dedicated adapter is preferable to silently extending `M.doc` fields that `M.snapshot` drops. A successful save must refer to the whole intended project. Keep explicit backup/export reachable even when browser storage is disabled.

Version and validate imported data before committing it. Reject unknown structural versions, non-finite values, impossible dimensions, excessive object/path counts, and unsupported geometry. Missing optional fields can use documented defaults; missing required physical units cannot be guessed for machining. Preserve the current project on failure and report the field or entity that needs attention.

The baseline canvas persists document and assets in separate writes. A broader project library should use an atomic record or a manifest/recovery strategy so a partial write cannot pair the wrong drawing with its assets. Browser-local autosave remains a convenience: an editable downloaded file is the student's portable record.

Undo/redo should operate at meaningful completed actions, including template replacement and imported changes. A canvas drawing undo must not silently revert unrelated project reflections or a different project. Cross-window handoff needs an explicit apply/replace rule, idempotency, and stale-project checks; reopening a canvas should not resend an old shape over a newer design.

## Assessment and accessibility

Build on `SC.Pr` and the hub's existing worked calculations rather than introducing a second incompatible answer checker. Keep four kinds of evidence separate: the design dimensions, the student's working, automated checks, and teacher judgement. A correct calculated area is evidence of numeracy; it does not establish that a selected tool, setup, or operation is appropriate.

Recommended initial reflection prompts are: “Which dimension mattered most?”, “Show one calculation you used”, and “What changed after you checked the design?” A later assignment file can add a rubric for unit use, dimension accuracy, coordinate reasoning, stock selection, process explanation, and inspection. Submission should be a deliberate student action and should preserve the exact revision submitted.

The baseline already offers keyboard and screen-reader hooks. Preserve them and test the whole student journey: template selection, field errors, stage navigation, canvas editing, transfer, export, and recovery. Provide numeric alternatives to dragging and a textual dimension summary alongside the preview. Feedback must not depend on colour alone. Help and error text should name the action the learner can take next.

## Implementation order

1. **Shared beginner workflow:** deliver the project model, five stages, starter shapes, explicit units/stock/fixed-origin conventions, save/open/undo, physical exports, supported canvas exchange, and a clear missing-receiver failure. Verify A01–A12 and A14–A16 for the supported subset; track unresolved scenarios explicitly.
2. **CNC convergence:** use the now-incorporated manual builder and simulator APIs, verify the adapter's precise setup/target semantics, verify A13 plus stale-project and unsupported-setup behaviour, then document the supported machining exercises. Reuse existing CAD/CAM modules for later geometry integration.
3. **Classroom breadth:** add reusable projects, differentiated modes, richer reflection/rubrics, inspection records, recovery help, and accessible object/coordinate editing. Test with students and instructors using realistic tasks.
4. **Geometry breadth:** add constrained sketches, common-scale assemblies, robust topology validation, SVG/DXF import, calibrated tracing, and teacher-authored fixtures. Preserve the same project method and file-version strategy.
5. **Advanced design/CAM:** consider text outlines, native desktop exchange helpers, nesting, richer solids/operations, postprocessors, collaboration, and LMS features as separately scoped releases with their own acceptance evidence.

The next design decision after the beginner slice is the operation/target contract for the CNC teaching tools. Setup and target reference transfer are the first step; linking a target contour to an operation and comparing the simulated result with the design are further work. Solving that boundary precisely prevents duplicate geometry editors, inconsistent units, and presentation drawings being mistaken for machining data.
