# Student design and machining integration: gap analysis

Audit date: 24 October 2026. Initial baseline: `abe5869`; updated after the parallel CNC release `4330ada` was incorporated. Scope: ACCESS Numeracy Hub, Shape Canvas, CNC learning tools, and the supplied desktop design references.

## Decision

Build one student method, **Brief → Draw → Check → Machine → Reflect**, around a versioned project with physical dimensions. Keep the existing Shape Canvas as the capable drawing and numeracy workspace. Add a guided entry point and an explicit geometry handoff to machining. The first release should complete this method for a small, well-defined set of parts; subsequent releases should expand the same contract.

“Integrate everything” is treated as a complete capability map and an ordered implementation programme. It does not mean that native desktop applications, their executable files, or every CAD/CAM feature can be embedded in an offline browser page.

## The student method

The method keeps the same project name, units, part, next action, and saved-version context across stages. Students can revisit an earlier stage; a material edit refreshes checks and invalidates dependent machining evidence. A stage indicator is navigation, not a claim that a student has completed or mastered it.

| Stage | Student question | Minimum interaction | Evidence carried forward |
|---|---|---|---|
| Brief | What am I making, and what must it fit? | Select a starter, name the part, state its purpose, choose display units, and enter stock dimensions. Show a labelled example. | Purpose, part family, canonical dimensions, stock, chosen coordinate origin, and optional requirements. |
| Draw | How will I describe its size and shape? | Enter dimensions with immediate preview; open the same supported part in Shape Canvas; use the existing formulas and dimension tools. | Parametric geometry and its source revision. Drawing annotations remain presentation information. |
| Check | Does my design meet the brief? | Show calculated values, dimensional validity, stock fit, unit interpretation, and an explicit list of remaining issues. Link each issue to the relevant field. | Check results associated with the exact project/geometry revision, plus the student's estimate or explanation. |
| Machine | How would the part be set up and made? | Show process, stock, origin, intended operation, and the connection to the CNC learning simulator. Separate simulation from physical-machine output. | A validated teaching handoff, operation/tool choices, interpreter diagnostics, and explicitly captured simulator estimates. |
| Reflect | What did I learn or change? | Record a calculation, explain one design change, and compare the result with the brief. Save an editable project and a useful presentation/export. | Reflection, saved versions, assignment criteria, entered rubric reviews, and a deliberate submission snapshot. |

Beginner mode should start from a plate, washer, or shaft and expose one decision at a time. Advanced mode should expose the same model's dimensions, setup, coordinates, and interchange choices without a different file format. Learners must not lose existing work when changing mode. “Advanced” means more control; it does not remove dimensional validation.

The first user test is deliberately practical: a student creates a dimensioned part, edits it in the canvas, checks its fit, reaches the machining activity, explains one result, and reopens their saved work without re-entering any dimensions.

## Canonical data and geometry contract

Use a design project envelope for the new method; keep legacy canvas drawings readable. Canonical physical lengths are mm. Display units and formatting are presentation choices. Retain full numeric precision in the model and round at display/export boundaries according to the specified purpose. Degrees/radians and area/volume powers must be explicit wherever values cross module boundaries.

The current contract identifies schema/version, project identity, brief, part type and dimensions, display units, stock, fixed-origin placement, and reflection. Optional `workflow` metadata contains revision, guided/advanced mode, checkpoints, inspections, an assignment, entered reviews, a legacy operation, optional ordered `sequence`, optional comparison goal, and recorded results. A sequence has version 1 and up to 12 uniquely identified, labelled steps containing explicit operation values. The sequence is authoritative when present; its first operation is mirrored for older summary readers. Pure dimensional/stock checks are recomputed; captured CNC evidence retains its source fingerprint. Do not put interface HTML or executable expressions in the model.

Canvas adapters must use `SC.M`'s semantic dimensions and document units. They must not derive a radius or part width from `getBoundingClientRect`, the page's zoom, a PDF paper scale, or `SC.A.exportSvg`'s presentation bounds. Baseline `M.addShape` uses `M.fitPpu` to fit each object on screen; two equal-looking objects can therefore represent different physical sizes.

A single parametric part transfers by shape ID plus semantic dimensions, with an explicit local origin. Its screen x/y, zoom, rotation, and ppu are presentation. Composite transfer instead incorporates member placement and rotation through the established common physical scale and `SC.Co` closed outline. Profiles normalize to X-right/Y-up mm, retain holes/nested islands/disconnected parts, and reject invalid topology. General independent-object assemblies still need a declared common scale and complete local → assembly → stock transform. Closed material loops and construction geometry must retain different semantics.

Stock must distinguish rectangular material from round stock, and 2D outline from 3D dimensions. A cylinder side view does not by itself define a turning setup. A washer outline does not by itself define drilling versus pocketing versus profiling. Keep **geometry**, **process intent**, **toolpath**, and **machine program** as distinct data stages. The existing CNC simulator uses inches internally in parts of its project model: `CNCManual.project` converts its mm/in setup to that representation. The design adapter should enter through `CNCManual`/builder APIs and respect their conversion, precision, and stock limits; it must not send canonical-mm stock straight into an internal-inch simulator object.

Checks are pure functions of validated project data. A passing check states its scope: “fits inside stock” is narrower than “ready to machine.” The CNC fingerprint covers project identity, geometry, stock, placement, display units, machine, and operation; sequence-enabled projects add the complete order/labels/operation values and explicit comparison mode/depth/tolerance/facing allowance. Legacy hashes remain unchanged until a project opts into the expanded contract, including old goals without the optional facing field; migration does not relabel old captures as newly checked. Numeracy-comparison and entered-inspection fingerprints cover identity/geometry. Reflection and marking changes do not invalidate machining captures. Hashes detect changes and are not tamper-proof signatures. Explicit incoming-project protection and best-effort library merging do not establish transactional cross-tab collaboration.

Comparison goals distinguish retained material from a pocket and include an optional explicit `faceAllowanceMm`. Its semantic default is zero; absence stays absent in old serialized goals and hashes. A mill target declares a positive depth within stock and tolerance in mm; the depth is always absolute below the original stock top. Its kept surface is `-faceAllowanceMm`, and its cut floor is `-depthMm`. Floor depth must be at least the allowance; equality describes a facing-only target. A cylinder target uses retained diameter/length with no milling depth. Its expected front is the original stock front minus the allowance; the design length starts there. Facing allowance plus design length must fit the exposed stock.

Without an explicit goal, milling starts with a pocket at the lesser of 2 mm or 20% of stock depth to match the recommended first operation. Lathe defaults to retained-solid; tolerance defaults to 0.1 mm. The intended goal is never inferred silently from operation values. Leading face operations use increasing cumulative amounts from the original stock face; lathe turn/part lengths start at the newly faced front, and parting runs last. The parting step-down is radial peck depth, not axial length. Generation adds the blade width behind the cut and 15.24 mm of simulated chuck clearance to its exposed-stock requirement.

Changing machine or stock remains editable: `comparisonState` returns safe effective settings and a review message without overwriting old settings/evidence. Saving the reviewed goal stores it explicitly. A captured comparison stores bounded scalar metrics, resolution/status, observations/limitations, optional sampled front/loose-length observations, and a compact map (at most 48 × 48 mill cells or 192 lathe diameter samples). Full simulator material arrays are excluded from project/library files. A sampled simulator comparison is separate from an entered physical inspection.

Mill comparison uses even-odd material regions, preserving holes/islands, and compares the expected top height with both actual top and bottom. Retained-solid mode counts surrounding waste as excess; a contour groove does not silently count as a completed part. Lathe comparison uses native samples inside the fixed target interval and excludes mounted chuck allowance; it does not interpolate shoulder material from outside the part. Native detached radius slices are retained before the mounted bar is cleared, bounded to 12 pieces/100,000 detached samples in transient snapshots. One loose piece can be measured, including excess beyond either intended end. Multiple pieces and old parted snapshots without native profiles report unsupported instead of guessing. Front and loose-length observations use signed actual-minus-expected errors; missing observations stay null. Each end has up to one axial sample of uncertainty (normally 0.127 mm); loose length has up to two spacings. Endpoint volume uses the nearest interior sample. Neither method certifies features between samples, physical tolerances, finish, deflection, bores, threads, or real manufactured dimensions.

## Persistence, undo, and import behaviour

Preserve the baseline canvas's document and assets when introducing design metadata. A shared-project envelope or dedicated adapter is preferable to silently extending `M.doc` fields that `M.snapshot` drops. A successful save must refer to the whole intended project. Keep explicit backup/export reachable even when browser storage is disabled.

Version and validate imported data before committing it. Reject unknown structural versions, non-finite values, impossible dimensions, excessive object/path counts, and unsupported geometry. Missing optional fields can use documented defaults; missing required physical units cannot be guessed for machining. Preserve the current project on failure and report the field or entity that needs attention.

The baseline canvas persists document and assets in separate writes. The new project library stores its entire validated record in one localStorage write, limited to 20 projects and 4 MiB. Each project retains up to 12 historical snapshots and a separate current head. Explicitly named snapshots are preserved before automatic edits are pruned; after all 12 slots are named, autosave can still update the current head. Another named save requires freeing a version slot. Full-library import preserves history and copies conflicting identities instead of replacing existing entries. A corrupt stored record is not automatically overwritten. Browser-local autosave remains a convenience: a downloaded project/library is the portable recovery record.

Undo/redo should operate at meaningful completed actions, including template replacement and imported changes. A canvas drawing undo must not silently revert unrelated project reflections or a different project. Cross-window handoff needs an explicit apply/replace rule, idempotency, and stale-project checks; reopening a canvas should not resend an old shape over a newer design.

## Assessment and accessibility

Build on `SC.Pr` and the hub's existing worked calculations rather than introducing a second incompatible answer checker. Keep four kinds of evidence separate: the design dimensions, the student's working, automated checks, and teacher judgement. A correct calculated area is evidence of numeracy; it does not establish that a selected tool, setup, or operation is appropriate.

Reflection prompts cover the important dimension, one calculation, and what changed after checking. Portable assignment files add criteria, dimensional requirements, and reflection prompts. Default criteria cover units, calculation, checking, process, and inspection/reflection; authoring can replace their titles. Reviews record explicitly entered scores/comments and an unauthenticated reviewer label. Requirements and tolerance comparisons do not award marks. Submission is a deliberate download preserving the editable project and its assessment snapshot.

The baseline already offers keyboard and screen-reader hooks. Preserve them and test the whole student journey: template selection, field errors, stage navigation, canvas editing, transfer, export, and recovery. Provide numeric alternatives to dragging and a textual dimension summary alongside the preview. Feedback must not depend on colour alone. Help and error text should name the action the learner can take next.
